# Record on LeetCode

Load apps/extension as an unpacked Chrome extension, reload version 0.8.0 after updates, restart the API, and refresh LeetCode. Start the local API first.

After a fresh submission transitions to Accepted, Recall opens a small on-page prompt. Choose On my own, With hints, or Read the solution. Choose at least one topic you actually used. These selections drive the classifier, with specialized topics taking precedence, and assign one primary pattern to both problem coverage and this practice record. Select Other to open a searchable list of all learning patterns and choose one directly. Selection is required; unrecognized topics must use Other. Provider tags stay intact, and additional checked tags do not refresh extra patterns. Save practice closes the prompt only after confirmed persistence.

Run, stale Accepted pages, failed submissions, repeated result renders, and navigation do not automatically open the prompt. Both Submit and Ctrl/Cmd+Enter arm detection. Run or navigation cancels a pending trigger. The extension toolbar can manually open the recorder; these entries remain distinguishable as self-reported practice.

An uncertain save freezes and preserves the exact UUID, timestamp, assistance, approach, topics and provenance in extension storage. Reopening restores it. Retry does not create another attempt. Definitive validation failures unlock editing; network/server failures keep the recording for retry. Changes and closing retain an editable draft. Extra Accepted submissions are queued, including when an older draft is restored. Confirmed saves show success feedback and open the next queued recording.

Use Check whether this recording was saved to reconcile an uncertain response. A matching saved request clears the local pending copy; a removed request directs you to dashboard recovery. A confirmed conflicting ID allows keeping an archived copy before starting a separate recording. Settings lists all local drafts, pending saves and queued submissions, and can download conflict choices.

The panel focuses its close button, supports Escape and returns focus without trapping the page. Time is recorded automatically and is not shown as a form field. Manual recording starts when the panel opens; Accepted evidence starts at detection time. Drafts, queued submissions and retries retain their original event time. Provider metadata is fetched if Topics is collapsed, without sending cookies to Recall. New saves verify the signed-in account and the API checks it against the bound workspace.

The form renders immediately and loads the pattern catalog in the background. Fresh saves carry a required classification choice that the API validates and resolves with the shared classifier. A selected traversal keeps the provider's Tree context, rather than becoming a Graph technique. Other can select any valid learning pattern; the unclassified fallback is not a manual learning choice. Topic selection can still save if catalog loading fails; Other offers Retry problem details until the catalog is available.

A confirmed save updates primary placement and the new attempt atomically. Older attempts retain their recorded unit. Retrying an already saved request does not restore an outdated primary placement. New request fingerprints use normalized user choices rather than the derived unit, so classifier refinements do not change retry identity. Legacy pending payloads without the new classification choice retain their original request hash, fields and retry behavior. Refresh the extension and restart the updated API together.

The controlled fixture is available with npm.cmd run test:capture at http://127.0.0.1:8765. It uses real adapter/panel code with simulated verdicts and saves. It is not proof of compatibility with the latest live LeetCode markup; verify the signed-in Chrome extension after loading updates.
